# 中文兜底检查

检查代码变更中是否存在中文兜底文本（即通过逻辑运算符、三元表达式、函数默认参数等方式硬编码的中文字符串），确保国际化一致性。

## 为什么需要检查

项目中已建立完整的 i18n 体系（`language.*` / `LanguageList[currentLanguage].*`），中文兜底文本存在以下问题：

1. **国际化失效**：用户切换到非中文语言时，看到的仍是中文
2. **翻译遗漏信号**：兜底往往意味着对应的 i18n key 未定义，应补充到 `LanguageList.json`
3. **维护陷阱**：兜底分散在各处，后续难以统一管理和翻译

## 检查流程

### 第一步：确定检查范围

**写入后触发** — 检查当前会话中 `Edit`/`Write` 工具写入或修改过的文件。

**手动调用** — 若用户指定了文件或目录，检查指定范围；否则检查 `git diff --name-only` 输出的变更文件。

只检查源代码文件（`.js`、`.jsx`、`.ts`、`.tsx`、`.vue`），跳过：
- JSON 配置文件（`LanguageList.json`、`package.json` 等）
- 纯数据/配置类文件（`VoiceCommand.js`、`language_cn_*.js` 等已知的中文数据文件）
- 测试文件（`.test.js`）
- `node_modules/`

### 第二步：扫描模式

对每个文件逐行扫描以下模式：

#### P0 — 逻辑运算符中文兜底（严重）
```js
const title = language.yoloWindowTitle || 'YOLO模型训练与部署';  // ← 检出
const name = obj.name ?? '默认名称';                             // ← 检出
```

正则：`\|\|\s*['"`]\s*[^'"`]*[一-鿿]` 或 `\?\?\s*['"`]\s*[^'"`]*[一-鿿]`

#### P1 — 三元表达式中文回退（严重）
```js
const label = key ? t(key) : '未命名';  // ← 检出
```

正则：`\?\s*.+\s*:\s*['"`][^'"`]*[一-鿿]`

#### P2 — 函数默认参数中文（建议）
```js
function show(name = '未命名') { ... }       // ← 检出
const fn = (msg = '操作成功') => { ... };    // ← 检出
```

正则：`=\s*['"][^'"`]*[一-鿿]`

#### P3 — JSX/模板中文硬编码（建议）
```jsx
<span>保存成功</span>                          // ← 检出
return `最多只能选择${n}个`;                   // ← 检出
```

注意：**仅报告同时包含 i18n 使用模式的同一文件中的硬编码**，避免对无 i18n 上下文的独立中文文案误报。

### 第三步：排除误报

以下情况不算兜底，不应报告：

- **以 `language.` 或 `LanguageList[` 开头的行** — 这些是 i18n key 的引用，不是兜底
- **注释中的中文**（`//` 或 `/* */` 内的内容）
- **console.log / console.error 中的中文**（调试日志）
- **已知的数据/配置文件**（以 `language_cn_` 开头、`VoiceCommand.js`）
- **Redux reducer 初始状态中作为 `name: '未连接'` 这类设备状态默认值** — 这些是领域数据而非 UI 文案（仅在有明确注释说明时豁免）

### 第四步：生成报告

若发现问题，按以下格式输出报告：

```
## 🔍 中文兜底检查报告

检查范围：<文件列表>
检查时间：<当前时间>

### 发现 N 处中文兜底

#### 🔴 严重 — 逻辑运算符兜底（共 X 处）

| # | 文件:行号 | 代码片段 | 建议 |
|---|----------|---------|------|
| 1 | src/views/YoloApp/index.js:124 | `language.yoloWindowTitle \|\| 'YOLO模型训练与部署'` | 在 LanguageList.json 中确认 yoloWindowTitle 的 CN 翻译已定义后，移除兜底 |
| 2 | ... | ... | ... |

#### 🟡 建议 — 函数默认参数中文（共 X 处）

| # | 文件:行号 | 代码片段 | 建议 |
|---|----------|---------|------|
| 1 | ... | ... | ... |

#### 🟢 提示 — JSX 中文硬编码（共 X 处）

| # | 文件:行号 | 代码片段 | 建议 |
|---|----------|---------|------|
| 1 | ... | ... | ... |

### 修复优先级

1. 先修复所有 🔴 严重项：确认对应 i18n key 已定义，然后移除兜底
2. 再处理 🟡 建议项：评估是否应使用 i18n
3. 最后确认 🟢 提示项：判断是否为有意为之
```

若无发现任何问题，仅输出：`## ✅ 中文兜底检查通过，无发现问题`

## 注意事项

- 不要仅依赖正则扫描，需结合上下文判断：该文件是否已引入 i18n（import/use language 相关模块），若整个文件无 i18n 上下文，P3 级可跳过
- 对于包含 `language.` 前缀的行，`||` / `??` 后的中文才是兜底，左侧引用本身不是问题
- 文件类型为 `.json` 时默认跳过（除非用户明确要求检查）
